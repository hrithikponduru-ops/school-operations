# Stage 2: Conflict-Free Course Timetabling (Integer Programming)
💡
**Question.** Assign 13 courses to 6 periods and 4 rooms so that no teacher or room is double-booked, every class fits its room, and as few students as possible have two classes at the same time.

**Answer.** A greedy spreadsheet-style assignment produces 81 student conflicts. The integer program produces 6, and the solver proves no assignment does better.

![conflicts](../figures/stage2_conflicts.png)

## The data

- 13 courses in 5 bands (math, science, english, history, elective), 9 teachers, in `data/courses.csv`
- 4 rooms with capacities 30, 30, 24, 18 and 6 periods, in `data/config.json`
- 45 students, 232 enrollments, in `data/students.csv`. Each student takes one course per band; about one in six adds a second course from some band. Generated by `make_data.py` with a fixed seed.

## The model

**Index sets**

- $c \in C$ courses, $p \in P$ periods, $r \in R$ rooms
- $t \in T$ teachers, with $C_t$ the courses teacher $t$ teaches
- $s \in S$ students, with $C_s$ the courses student $s$ takes

**Data**

- $e_c$: enrollment of course $c$
- $\kappa_r$: capacity of room $r$

**Decision variables**

$$x_{c,p,r} \in \{0,1\} \quad \text{course } c \text{ meets in period } p \text{, room } r$$
$$y_{c,p} = \sum_{r} x_{c,p,r} \quad \text{(helper: course } c \text{ meets in period } p\text{)}$$
$$v_{s,p} \in \mathbb{Z}_{\ge 0} \quad \text{conflicts student } s \text{ has in period } p$$

**Objective**

$$\min \sum_{s \in S} \sum_{p \in P} v_{s,p}$$

**Hard constraints** (a school cannot break these)

$$\text{(1) once: } \sum_{p}\sum_{r} x_{c,p,r} = 1 \qquad \forall c$$
$$\text{(2) room: } \sum_{c} x_{c,p,r} \le 1 \qquad \forall p, r$$
$$\text{(3) teacher: } \sum_{c \in C_t} y_{c,p} \le 1 \qquad \forall t, p$$
$$\text{(4) fits: } x_{c,p,r} = 0 \text{ whenever } e_c > \kappa_r$$

**Soft constraint** (violations are counted, then minimized)

$$\text{(5) conflicts: } \sum_{c \in C_s} y_{c,p} - 1 \le v_{s,p} \qquad \forall s, p$$

If student $s$ has two courses in period $p$, the left side is 1 and $v_{s,p}$ is forced to at least 1. If they have zero or one course, the left side is at most 0 and $v_{s,p}$ can be 0. Because $v$ is minimized, it equals exactly the number of extra courses beyond the one the student can attend.

## Three modeling techniques used

**Soft constraints.** Making (5) hard would ask the solver "is a perfect timetable possible?" and it would answer *infeasible* with no further help. Making it soft asks "how close to perfect can we get?" which always has an answer and tells us the answer is 6.

**Domain reduction.** Constraint (4) is not written as a constraint. The variable $x_{c,p,r}$ is simply never created when the class does not fit the room:

```python
x = {(c, p, r): LpVariable(...) for c in C for p in P for r in R
     if d.courses.loc[c, "enroll"] <= d.rooms[r]}

```

Fewer variables, and the constraint cannot be violated because there is nothing to violate it with.

**Symmetry breaking.** Periods are interchangeable: any solution stays valid if you relabel period 1 as period 4. So are the two 30-seat rooms. Without help the solver explores every relabeling as if it were new. Two constraints remove that:

$$\text{(S1) } y_{c_1, 1} = 1 \qquad \text{(the first course is in period 1, without loss of generality)}$$

$$\text{(S2) } \sum_c x_{c,p,R102} \le \sum_c x_{c,p,R101} \qquad \forall p \qquad \text{(use R102 only if R101 is used)}$$

Neither changes the optimal value. They only remove duplicate solutions.

| Math | `model.py` |

## Why proving optimality takes a minute

The solver finds the 6-conflict schedule in a couple of seconds. The remaining time is spent proving that 5 is impossible.

Branch-and-bound proves optimality by comparing the best integer solution to the *LP relaxation* bound, where the binaries may take fractional values. Here the relaxation can put a course 50% in period 1 and 50% in period 2, which makes every student's per-period load at most 1 and gives a lower bound of **0** conflicts. That bound is useless, so the solver has to search nearly the whole tree. Model size: 276 binary $x$ variables and 270 integer $v$ variables.

Two things would tighten it:

* **Aggregated conflict cuts.** Right now each student contributes their own weak inequality. Summing (5) over all students who take a given pair of courses $a, b$ gives $n_{ab}(y_{a,p} + y_{b,p} - 1) \le \sum_s v_{s,p}$ for each period, where $n_{ab}$ is the number of students taking both. These are implied by the model but not by its LP relaxation, so adding them raises the lower bound above zero.
* **A better instance.** The first version of this data gave every two-course band the same teacher, which made the optimum 31 conflicts and the proof take longer than 3 minutes. Spreading teachers across bands, as a real school does, brought it to 6 conflicts and about 60 seconds. Data realism and solver speed are linked.
